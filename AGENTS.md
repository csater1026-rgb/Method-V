# Method V

Read `PLAN.md` for the product plan and `README.md` for setup and how the code is laid out.

- Next.js 16 App Router + Supabase. `src/proxy.ts` is the old "middleware" (renamed in Next 16). `params`, `searchParams` and `cookies()` are async.
- With no Supabase keys the site runs in demo mode using `src/lib/demo.ts`. Every read in `src/lib/data.ts` and every action in `src/app/actions.ts` must keep working (or explain itself) in demo mode.
- The database is the source of truth for rules: lists of categories, roles, pricing and stages live in both `src/lib/constants.ts` and the check constraints in `supabase/migrations/` — change both together. Add a new migration file rather than editing an applied one.
- Writes from the browser are limited by column grants and row level security. Counters (likes, comments, tries, followers) are trigger-only. `link_checked_at` is only set by the server with the secret key, after `checkLink()` passes.
- Placement and perks are database-enforced: tester ranks (`tester_rank()`, mirrored by `TESTER_RANKS`/`testerRank()` in constants), launch days, boosts and swaps only change through the security-definer functions in the Phase 3 migrations; `launch_at`, `boosted_until` and `featured_until` aren't in any column grant.
- Phase 2: messages are only insertable between connected people (`are_connected()` in the insert policy); notifications only come from `public.notify()` called by triggers — add a trigger (not app code) for new notification kinds, and add the kind to the check constraint and to `describe()` in `src/components/Inbox.tsx`.
- App pages put Comments, Q&A and Updates in tabs (`?tab=qa|updates`, default comments) under `#discuss`; keep new discussion features in that tab bar rather than stacking more sections.
- Credits: balances change only via rows in `credit_events` (trigger-applied, never negative). The credit amounts live in both `CREDITS` in `src/lib/constants.ts` and the Phase 3 migration — change both together. Feedback is private to tester and builder; only totals on `apps` are public.
- `src/lib/link-check.ts` makes server-side requests to user-supplied URLs; keep its private-address blocking and per-connection DNS check intact.
- "Try it" buttons are plain `<a href="/try/<slug>">`, not `next/link`, so prefetching never counts as a try.
- Posting: `/submit` is two steps (video, then link). `previewLink()` reads the site through `fetchPage()` (same private-address protection as the link check; signed-in only) and `sitePreview()` in `src/lib/site-preview.ts` turns it into name/tagline/description/category; auto-fill never overwrites a field the person typed in. On phones the tab bar's + is a file input that hands the video over via `src/lib/pending-video.ts`.
- Signed-out actions call `useSignIn()` (the sheet in `src/components/SignIn.tsx`) instead of navigating to `/login`, so people stay where they were.
- Phase 4 (Earn): money only moves through `prepare_payment()` (called as the payer) and `complete_payment()` (secret key, from the signed Stripe webhook). Payouts use `start_payout()`/`finish_payout()`, and refunds use `payments.refund_cents` plus `mark_refunded()`. Those server-only functions have `execute` revoked from anon/authenticated; keep it that way for any new one. `payments`, `earnings`, `payouts`, `backings`, `sponsorships` and `sponsored_tries` have no browser writes. `backings.amount_cents` isn't granted for select, so the public wall never shows amounts. Amounts are whole cents. `EARN` in constants mirrors the numbers in the Phase 4 migration: change both together. Stripe is called over REST in `src/lib/stripe.ts`, with no SDK. Every call must fail closed when `isStripeConfigured` is false and use an idempotency key when it moves money. Sponsor cards (`SponsoredBy`) are always labeled Sponsored and link to `/try/<sponsor>?s=<deal>` as a plain `<a>`.
- Phase 5 (Scale): every "Try it" link carries `?via=<source>` (`TRY_SOURCES` in constants mirrors the check on `try_clicks.source`), so new Try links need a source. Analytics come only from `app_daily()`/`app_sources()`: owner only, with more than 7 days needing Pro. Brands go live after the server's link check and can sponsor only once `verified_at` is set by the team. Brand links go through `/go/<slug>`, and `record_sponsored_try` takes the app or brand id the person landed on. The public API (`src/lib/api.ts`, `/api/v1`) is read-only. Map rows through the `public*` helpers so nothing private or internal leaks. `next.config.ts` denies framing everywhere except `/embed/`, and the embed must stay script-free. `public/sw.js` only serves the offline page; don't make it cache data. `src/lib/pixel-icon.ts` must match `src/app/icon.svg` (the unit tests check).
- The native app lives in `mobile/` (Expo). Read `mobile/AGENTS.md` before touching it. It has its own tooling and is excluded from the website's tsconfig and eslint. It imports `src/lib/constants.ts`, `types.ts`, `demo.ts` and `format.ts` directly, so keep those free of server-only imports. Posting from the app goes through `/api/mobile/apps` → `publishApp()` in `src/lib/publish.ts`, the same code the website's `createApp` uses.
- Sign-in: email + password (`passwordAuth`), emailed link (`signIn`), and optional providers. `MIN_PASSWORD` in constants applies to both the website and the app.
- Before committing: `npm run lint`, `npx tsc --noEmit`, `npm run test:unit`, `npm run test:db`, and `npm run test:ui` against a running build.
- Design: "drop culture meets the late-night code editor" in sage and cream, mobile-app first, with light and dark themes. Tokens live in `@theme` in `src/app/globals.css` (dark values) with the light values below it; use the tokens, never raw colors. The theme follows the phone unless the toggle (`ThemeToggle`) set `data-theme` via the `theme` cookie. Anything drawn on video or posters goes inside `media-dark` so it stays dark in light mode. Fonts: `display` utility (Big Shoulders, uppercase) for headlines, Schibsted Grotesk for text, Martian Mono (`font-mono`, `tag`) for numbers, timers, credits and labels. Motion is limited to the `rise` entrance (set `--i` for stagger), the feed caption reveal, the like pop and the `PixelCoder` mascot (header logo, footer masthead, loading screens; `pc-*` rules in globals.css), and is switched off under `prefers-reduced-motion`. `loading.tsx` lives only in `drops/`, `browse/` and `test/`: a loading boundary makes pages stream, which turns `notFound()` into a 200, so keep it off app and profile pages. Phones get the bottom tab bar (`MobileTabs`, height `--tabbar`); keep tap targets ≥ 40px.
